## Встановлення і запуск

Потрібен Python 3.11 або новіший. Команди виконуються з каталогу проєкту в macOS або Linux.

```sh
git clone https://github.com/LoFiSwanL/Lab_TP.git
cd Lab_TP
python3 -m venv .venv
source .venv/bin/activate
python -m pip install .
python -m unittest discover -s tests -v
```

Після встановлення доступні команда `sipl` і рівнозначний запуск через `python -m sipl`.
Версії бібліотеки Lark і засобу збірки задані в `pyproject.toml`.

| Команда | Призначення |
|---|---|
| `sipl parse FILE` | Побудувати типізоване абстрактне синтаксичне дерево з позиціями |
| `sipl check FILE` | Перевірити синтаксис програми |
| `sipl run FILE` | Виконати програму за її AST |
| `sipl trace FILE` | Виконати AST і показати події |
| `sipl term FILE` | Побудувати семантичний терм у нотації курсу |
| `sipl eval FILE` | Застосувати терм до стану і показати кроки за правилами AF |

Програма читається з файла UTF-8 або зі стандартного вводу, якщо замість `FILE` вказати `-`.
Для `run`, `trace` та `eval` початковий стан передається як JSON-об'єкт через `--state`.
Якщо стан не вказати, він порожній. Імена чутливі до регістру, а значення мають бути цілими числами.

```sh
sipl check examples/power.sipl
sipl parse examples/power.sipl --json
sipl run examples/power.sipl --state '{"X":5,"Y":2}'
sipl trace examples/gcd.sipl --state '{"M":8,"N":16}' --json
sipl term examples/power.sipl
sipl eval examples/power.sipl --state '{"X":5,"Y":2}'
sipl run examples/condition.sipl --state '{"X":1,"Y":0}'
```

У першому прикладі обчислюється `5^2 = 25`, у другому `НСД(8, 16) = 8`.
Третій приклад перевіряє диз'юнкцію, заперечення, дужки та `skip`.

## Звідки береться результат

Парсер застосовує [граматику Lark](src/sipl/grammar/sipl.lark) і перетворює дерево розбору
на власне AST. Кожен вузол AST має `SourceSpan` з початком і кінцем у тексті.
`run` проходить AST та змінює стан згідно з операторами програми. У `trace` ті самі
обчислення породжують події, зокрема перевірку умови і зміну змінної.

`term` рекурсивно замінює конструкції AST композиціями програмної алгебри.
Наприклад, `R := R * X` дає `AS^R(S²(mult, R⇒, X⇒))`. `eval` читає вже отриманий терм
і застосовує формули AF. Для присвоювання спочатку обчислює значення виразу,
потім накладає на стан одну пару з іменем змінної. Перехід записується як `AF_AS`
зі станом до і після присвоювання.

Запуск як бібліотеки використовує ці самі операції.

```python
from sipl import build_term, evaluate, format_term, parse, run

ast = parse("begin R := X + 1 end")
initial = {"X": 5}
events = []
result = run(ast, initial, on_event=events.append)

term = build_term(ast)
proof = []
semantic_result = evaluate(term, initial, on_step=proof.append)
print(format_term(term))
print(semantic_result.final_state)
```

## Помилки, ліміт і JSON

Відсутнє значення змінної робить обчислення невизначеним. Обидва способи
обчислення зупиняються на ліміті кроків. Один крок нараховується за
присвоювання, `skip` або перевірку умови `if` чи `while`, включно з
останньою хибною перевіркою `while`. Початковий ліміт становить 10 000.
Його можна задати через `--max-steps`. Статус `limit` означає, що в межах
заданого бюджету кінцевий стан не отримано. Дуже глибоко вкладені
обчислення також можуть досягти ліміту рекурсії Python.

Усі команди мають режим `--json`. У [схемі JSON v1](src/sipl/result-v1.schema.json)
задані поля AST, терму, подій, кроків AF і діагностик. Структуру відповіді та
коди завершення описано в [контракті CLI](docs/cli.md).

## Перевірки й джерела

- Тести синтаксису містять 16 правильних і 21 неправильну програму. Тести AST
  перевіряють типи вузлів, пріоритети й точні позиції.
- Тести обчислень перевіряють стани, обидві гілки `if`, ліміт, невизначеність,
  послідовність подій та кроки AF. Три текстові еталони перевіряють нотацію терму.
- Інтеграційні тести запускають CLI окремим процесом і перевіряють JSON та коди завершення.
- [Специфікація лексики та граматики](docs/syntax.md) зіставляє правила реалізації
  з практикумом (2024, с. 8-10) і посібником Нікітченка (2010, § 1.2, с. 7-11).
- Побудова й обчислення термів відповідають практикуму (с. 13-17) та посібнику
  Нікітченка (§§ 1.3.3-1.3.7, с. 14-21). Програму степеня взято з практикуму,
  а програму НСД з прикладів Нікітченка.

На чистій копії репозиторію з Python 3.11 пройшли всі 26 тестів. Покриття
рядків AST, парсера, інтерпретатора й спільних моделей становить 96%.
Його можна відтворити в тому самому віртуальному середовищі.

```sh
python -m pip install 'coverage==7.17.3'
python -m coverage run --source=sipl -m unittest discover -s tests
python -m coverage report \
  --include='*/sipl/ast.py,*/sipl/model.py,*/sipl/parser.py,*/sipl/interpreter/*' \
  --fail-under=80
```
